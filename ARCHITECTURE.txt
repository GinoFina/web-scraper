===============================================================================
SOFASCORE SCOUTING APP - SYSTEM ARCHITECTURE (V2)
===============================================================================

1. PROJECT OVERVIEW
-------------------------------------------------------------------------------
Desktop application for a sports scouting agency. Extracts massive statistical 
data from the Sofascore API, processes it mathematically to evaluate specific 
profiles (Roles) using a DAX-like engine, and visualizes data in custom charts.

Migrated from a monolithic Python script to a modern full-stack architecture.

2. TECHNOLOGY STACK
-------------------------------------------------------------------------------
- Backend / API Layer: Python 3.11+ with FastAPI (local REST + WebSocket).
  Virtual environment: backend/.venv/
- Data Processing:     Pandas & Numpy (percentiles, scoring, normalization).
- Scraping Engine:     curl_cffi (TLS/Cloudflare fingerprint evasion).
- Database:            SQLite3 (local, WAL mode, normalized schema).
- Frontend:            React (Vite) + TailwindCSS v4 + TypeScript.
- Visualizations:      Apache ECharts (via echarts-for-react).
- State Management:    Zustand.

4. RUNNING THE APPLICATION
-------------------------------------------------------------------------------

  # Backend (from project root):
  cd backend
  .venv\Scripts\activate            # Windows
  uvicorn main:app --reload --port 8000

  # Frontend (from project root):
  cd frontend
  npm run dev                        # Starts on http://localhost:5173

  The Vite dev server proxies /api/* and /ws/* to the FastAPI backend.

5. SCRAPER PIPELINE
-------------------------------------------------------------------------------
When a league URL is submitted via the Sync Panel, the pipeline runs 4 stages:
  1. Download: Fetches all player stats (including basic running stats) page by page from the league API.
  2. Enrich: Fills in missing specific_position, nationality, age, and running distance via individual player endpoints.
  3. Recalculate: Derives computed fields (percentages, totals, "Total" consolidated row).
  4. Evaluate: Calculates DAX-like scores (world_score, league_score) based on roles.
  
This runs as a single atomic pipeline. WebSocket broadcasts real-time logs.
Running stats (distance, sprints, speed) are supported for seasons 25/26 onwards.

6. DATA PROCESSING (EVALUATOR)
-------------------------------------------------------------------------------
Mathematical operations are handled in backend/core/analytics.py and backend/scraper/evaluator.py:
  - Percentile ranking within position groups (Radar charts)
  - Min-max normalization (0-1) across global/league pools (Evaluator)
  - Weighted role scoring based on scoring_config.py definitions
  - Positional average computation for chart baselines

CRITICAL RULE: Frontend never touches the DB. It only consumes JSON from FastAPI.
Heatmaps are fetched LIVE by the frontend via the `/api/reports/heatmap/` proxy, never stored in DB.

7. ANTI-BAN STRATEGY
-------------------------------------------------------------------------------
All scraping uses curl_cffi with Chrome TLS fingerprint impersonation.
API URL structure uses `/unique-tournament/{id}/season/{id}/statistics/overall`.
Rate limiting (configurable delay between requests) is enforced.
The scraper runs in a background thread via asyncio.to_thread() to avoid
blocking the FastAPI event loop.
